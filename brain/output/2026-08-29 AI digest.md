## Worth your time

- **[CortexReach/memory-lancedb-pro](https://github.com/CortexReach/memory-lancedb-pro)** — A production-shaped LanceDB plugin bundling hybrid (vector+BM25) retrieval, cross-encoder rerank, and multi-scope isolation in one OpenClaw-compatible package; concrete reference for wiring hybrid search into an existing agent memory layer.
- **[cortrix/cortrix](https://github.com/cortrix/cortrix)** — Agent-first memory infrastructure exposing hybrid P-HNSW + BM25, cross-namespace queries, and an MCP server with Python SDK; directly maps onto the "markdown second brain + MCP" stack.
- **[Anserini Gets Dense Retrieval: Integration of Lucene's HNSW Indexes](http://arxiv.org/abs/2304.12139v1)** — Shows how a mature lexical toolkit (BM25/SPLADE) now ships HNSW dense indexes in the same engine, which matters because it lets you stop bolting a separate vector DB onto your search server.
- **[CaSKG: Counterfactual-Causal Skill Graphs for Scalable Agent Skill Retrieval](https://huggingface.co/papers/2608.25500)** — Argues skill libraries should be retrieved as a graph with causal structure, not as flat nearest-neighbor vectors; a real cost/latency lever if your agent re-injects skill prompts every turn.

## Patterns

- Hybrid (BM25 + dense) is now table stakes — every new retrieval repo ships both, fusion (RRF or learned) and a cross-encoder rerank on top. The differentiator left is *what* you index, not *how*.
- Agent-specific retrieval is splitting from generic RAG: skill graphs (CaSKG), memory plugins (LanceDB-pro, cortrix), and MCP-native code search treat retrieval as a memory layer with namespaces, scopes, and durability — closer to a database than a search box.
- Conspicuously absent: anything on incremental indexing, decay/pruning of old notes, or evaluation harnesses for a personal corpus. Everyone ships the read path; nobody is shipping the maintenance loop your second brain actually needs at month 12.
